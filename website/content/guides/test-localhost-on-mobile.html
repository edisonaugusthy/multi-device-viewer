Preview localhost at mobile widths in desktop Chrome

  1. Start your development server and open its actual URL in Chrome, for example http://localhost:5173/checkout.
  2. Open Mobile View from that tab. Use phone, tablet, and desktop presets to review the same route side by side.
  3. Keep the same cart or test data in each preview. Check that a sticky checkout button stays visible, the address form fits without horizontal scrolling, and errors remain readable at your narrowest supported width.
  4. Use your project’s CSS breakpoint for the final check. For a breakpoint at 768px, compare 767px and 768px to see exactly what changes.

For a single viewport with the CSS inspector open, use Chrome DevTools Device Mode. Both desktop methods can run while your server listens only on your computer.

Open a local website on an iPhone or Android phone

localhost on a phone points to the phone itself. On a trusted Wi-Fi network, use the development computer’s local IP address and the same port.

  1. Connect your phone and computer to the same trusted local network.
  2. Use your development server’s host setting to allow local-network connections. Find the network URL it prints, or look up the computer’s local IP address in its network settings.
  3. On your phone, open the address with the port and route, for example http://192.168.1.20:5173/checkout. Use your computer’s actual address and server port.
  4. Run your real-device checks and return the dev server to local-only listening when you are finished.

Use USB port forwarding on Android

If the Wi-Fi network blocks devices from reaching each other, use Chrome DevTools USB port forwarding. Forward an Android port to the computer’s local server, then open that port at localhost in Chrome on Android.

Troubleshoot common localhost problems

  • The phone times out. Check the IP address, server port, listening interface, and local firewall rules. Guest Wi-Fi can isolate devices even when both show the same network name.
  • The page opens but data or sign-in fails. On the phone, a hard-coded API URL at localhost points to the phone. A LAN IP also changes the page origin, which can affect development cookies and OAuth redirect URLs. Check your development configuration and test credentials.
  • Camera or other browser APIs fail over HTTP. Some APIs need a secure context. A plain HTTP LAN address can behave differently from localhost. Use your project’s trusted local HTTPS or staging setup for those checks.
